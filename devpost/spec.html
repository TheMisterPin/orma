Spec · proof of concept

Orma

Blueprint: Next.js API routes, Postgres via Prisma, shrunk photo blobs, AI SDK captions, Nominatim addresses, Leaflet on the place view.

Draft — review

Canonical plan: devpost/spec.md. This page is the visual companion.

How this works. Sign in → upload one photo → read place and time → resolve an address → generate a caption with the AI SDK (Ollama now) → edit → save image bytes and evidence in Postgres → browse by day or place. Place browse draws a Leaflet map with pins. No map on the single-memory detail screen.

Core journey through the system

Landing → log in

prd.md › Landing and access

Public page explains Orma. NextAuth: Google or email/password (JWT). Diary routes load only that user’s rows from Postgres.

Upload + evidence

prd.md › Upload and metadata extraction

One image. EXIF → lat/lng/time. Nominatim → address. Shrink image. Both place and time required before Generate; manual + current location/time if missing.

Generate caption

prd.md › Generate memory

API sends image + place/time through the AI SDK. Ollama locally for now; swap provider later. Caption is editable; must not invent place/time against evidence.

Save + browse

prd.md › Save and diary browsing · Tags

Memory row with shrunk Bytes, caption, address, coords, time. Home lists update. Tags via join table. Detail shows place, day, caption — no map.

Place view + Leaflet

prd.md › Evidence inspection · learning stretch

Browse by place → list + Leaflet map. Pins from stored coordinates. Build check: one pin first, then many.

Where it runs

Local: install → .env → Prisma migrate → Ollama (if local AI) → next dev → http://localhost:3000.

Production: Vercel + learner’s Postgres URL and secrets. Demo video + public GitHub still required for submission.

Failure modes

Missing place or time

Error + manual entry; both required before Generate.

AI or Nominatim down

Clear retry message; manual place name if geocode fails; never invent caption or address.

Image too large

Shrink first; reject if still over limit — Postgres blobs stay small.
